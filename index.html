Recent Decisions

How I think about trade-offs: the decisions behind the projects, not just the results.

Railway over K8s

Exportee-Rails · ADR-0001

Picked Railway PaaS over Kubernetes for a 4-container app with one user. The "shows I know K8s" resume argument doesn't hold — reviewers see a Helm chart for low-traffic and think over-engineered, not impressive. Committed Docker Compose anyway for the self-hosting story.

Read full ADR →

Pluggable Broker

Agentic Portfolio · ADR-001

Designed a Broker interface so the strategy and runner code never touch broker specifics. Paper-to-live (PaperBroker → Alpaca/IBKR) becomes a config swap, not a rewrite. Trade-off accepted: an extra abstraction layer the day-1 paper trader doesn't need, paid for by future flexibility.

Read full ADR →

Vendored CDN Libs

This portfolio · PR #70

Pa11y was disabled in CI because Three.js / D3 / Mermaid loaded from CDN stalled headless Chrome. Vendored Three.js + D3 locally (~950 KB) and lazy-loaded Mermaid on first modal open. Result: hermetic accessibility tests on every push, plus a real production perf win.

Branch-Based Deploys

This portfolio · ADR-003

Master pushes deploy to production (cjunker.dev); feature branches deploy to staging (staging.cjunker.dev) via a separate gh-pages repo. Lets every PR get a real preview URL without disrupting prod. Skip-staging escape hatch for Dependabot PRs.

Read full ADR →

Silence First

nitpick · prompt v2

First-pass review prompt overflagged — F1 0.16 on a noisy 91% rate. Rewrote with a default-to-silence rule and a 90% confidence threshold; F1 climbed to 0.46 on Sonnet 4.6, noise dropped to 50%. The reverted alternative (looser threshold to lift Sonnet recall) crashed precision 0.50 → 0.14 with no recall gain — a committed data point. Reviewer trust is built by not crying wolf.

Exportee-Rails Architecture

Multi-tenant config-as-code data pipeline platform

Key Architectural Decisions

Why these choices

  • Rails over FastAPI: intentional rewrite for AI-tooling support and faster team onboarding
  • OrgScoped concern: tenant isolation enforced at the query layer, not per-controller
  • Frozen CompiledDefinition: every ExportRun snapshots its exact config — re-derivable + tamper-evident
  • Polars (optional): 10–100× speedup vs row-by-row, swappable per pipeline
  • Lockbox encryption: source credentials encrypted at rest, decrypted at runtime only
  • Streaming PostgreSQL COPY: low-memory extraction for large tables

Agentic Portfolio Architecture

LLM-driven paper trading with pluggable broker abstraction

Key Architectural Decisions

Why these choices

  • Broker interface (ADR-001): paper-to-live by config change, not rewrite — strategy and runner code never touch broker specifics
  • Deterministic idempotency keys: safe re-runs after crash; same date+ticker+side never double-executes
  • Atomic JSON writes: temp file + os.replace prevents partial-state corruption during crash
  • Append-only JSONL: orders / decisions / equity logs are immutable audit primitives
  • LangGraph parsing: regex on **Rating**: line — explicit contract with the agent's output, not eval()
  • Per-ticker error isolation: one failure doesn't kill the run; partial results persist
